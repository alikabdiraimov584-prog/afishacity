# FREE — AI-консьерж свободного времени в Москве

Мобильное приложение (iOS, Capacitor) и бэкенд: разговорный интерфейс, который ищет реальные места
и события в live-источниках и ведёт пользователя к действию — бронь, билеты, маршрут, план вечера.

- `app/` — приложение (см. [app/README.md](app/README.md))
- `server.mjs` и модули — бэкенд, который приложение вызывает по HTTPS
- `public/` — интерфейс; в приложении он же работает внутри нативной оболочки

## Запуск

Нужен Node.js 20+. Единственная зависимость — `@anthropic-ai/sdk`.

```bash
npm install
cp .env.example .env   # вписать ANTHROPIC_API_KEY
npm start              # http://localhost:3000
```

Без `ANTHROPIC_API_KEY` интерфейс работает в режиме резервного опросника на встроенных данных.
С ключом включается консьерж: свободный диалог через Claude (Messages API, модель
`claude-opus-5` по умолчанию) с инструментом `recommend_free`, который ищет по живым источникам.

Сервер слушает только `127.0.0.1`.

## Структура

| Файл | Назначение |
|---|---|
| `server.mjs` | HTTP-сервер, статика из `public/`, API, диалог с Claude (tool use), обогащение карточек метаданными страниц |
| `providers.mjs` | Live-источники: KudaGo, Timepad, OpenStreetMap/Overpass, 2GIS (по ключу). Построение плана поиска из запроса |
| `live_ranker.mjs` | Фильтрация и ранжирование результатов, «ДНК места», учёт Taste Graph, геолокации, погоды и часов работы |
| `cache.mjs`, `hours.mjs`, `warmup.mjs` | Надёжность поиска: кеш ответов провайдеров с предохранителем, разбор часов работы, прогрев популярных запросов |
| `public/planner.js`, `planner.mjs` | Планировщик вечера: связка 2–4 точек, слоты времени, переходы пешком/такси, маршрут. Работает и в браузере, и на сервере |
| `store.mjs` | Хранилище на встроенной SQLite (`data/free.db`): пользователи, профиль, сохранённое, план, история вечеров, события для обучения вкуса, диалоги, общие планы |
| `telegram.mjs` | Проверка подписи initData Telegram Mini App и лимит запросов |
| `public/preview.html` | Предпросмотр интерфейса в рамке iPhone для широких экранов (`/preview.html`); на телефоне открывает приложение напрямую |
| `public/index.html` | Одностраничный UI: чат, карточки, план, сохранённое, Taste Graph, голос |

## API

| Метод и путь | Описание |
|---|---|
| `GET /api/health` | Готовность текстового AI, голоса и провайдеров |
| `POST /api/recommend` | Поиск по живым источникам. Тело: `{query, party_size, after_time, target_date, max_price_rub, area, taste_weights, user_location, weather_context}` |
| `POST /api/dialogue` | Диалог через Claude с инструментом `recommend_free`. Тело: `{message, previous_response_id, context}`; ответ содержит `response_id` — идентификатор истории, которую сервер хранит 2 часа. Требует `ANTHROPIC_API_KEY` |
| `POST /api/dialogue/stream` | То же, что `/api/dialogue`, но ответ приходит потоком Server-Sent Events: события `delta` (текст), `status` (что ищет агент), `break`, `done` (полный результат) и `error` |
| `GET /api/img?u=` | Прокси картинок мест: обходит защиту от хотлинков и смешанный контент, отдаёт только изображения до 3 МБ |
| `POST /api/plan` | Собрать план вечера: `{stops:[{query}], start_time, party_size, max_price_rub, target_date, anchor}` |
| `POST /api/plan/share` | Сохранить план и получить ссылку `/p/:id` (страница для отправки друзьям) |
| `GET /api/me` | Профиль: вкус, сохранённое, план, последние вечера, статистика, id последнего диалога. Пользователь определяется по подписи Telegram или заголовку `X-Free-Client` |
| `PUT /api/me` | Обновить вкус / сохранённое / план (частично) |
| `POST /api/me/event` | Действие с местом (`select`, `save`, `book`, `plan_add`) и его «ДНК» — сервер сдвигает Taste Graph и возвращает новый |
| `POST /api/me/evenings`, `DELETE /api/me/evenings/:id` | История собранных вечеров |
| `GET /api/weather` | Прогноз Open-Meteo по `lat`/`lon` |
| `POST /api/live-session` | Возвращает 501: голос работает через распознавание речи в браузере и обычный `/api/dialogue` |

Результаты `/api/recommend` кешируются на 5 минут по аргументам запроса.

Диалог использует адаптивное размышление Claude с уровнем `CLAUDE_EFFORT` (по умолчанию `medium`),
кеширование системного промпта и серверный fallback на другую модель Anthropic при отказе
по политике (`fallbacks: "default"`). Голосовой WebRTC-режим прежнего бэкенда убран:
у Claude нет realtime-канала, поэтому речь распознаёт браузер.

## Надёжность поиска

Ответ каждого источника (KudaGo, Timepad, Overpass, 2GIS) кешируется в `data/live_cache.json`
по параметрам запроса: 10 минут ответ считается свежим, до 6 часов — резервным. Если источник
упал или отвечает одними ошибками, отдаётся резервный ответ, а после трёх сбоев подряд
предохранитель пропускает источник на 5 минут. В ответе `/api/recommend` есть `degraded`
и `from_cache` по каждому источнику, а в `note` — пометка «Часть источников временно недоступна».
Прогрев (`warmup.mjs`) через 10 с после старта и затем каждые 30 минут последовательно прогоняет
популярные запросы («бар», «стендап», «с детьми» и т.д.); отключается `FREE_WARMUP=0`.
Часы работы из OSM `opening_hours` и строк KudaGo/2GIS («пн–вс 12:00–02:00», «круглосуточно»)
разбирает `hours.mjs`: закрытые к `after_time` места отсеиваются, открытые получают небольшой
бонус, закрывающиеся в течение часа — штраф; в карточке есть `open_now` и `closes_at`.

## Демо без бэкенда

Опубликованная как артефакт claude.ai страница умеет вести диалог через Claude прямо со страницы
(возможность `sample`): модель получает инструменты `recommend_free` и `plan_evening`, которые
исполняются в браузере по встроенному набору мест. Так демо тестирует настоящие диалоги без сервера.
В приложении и на сервере этот режим не используется — там работает `/api/dialogue`.

## План вечера

Фраза вида «поужинать, потом в бар, а после кальян» превращается в план: агент (инструмент
`plan_evening` у Claude или разбор фразы в резервном режиме) ищет каждую точку рядом с предыдущей,
расставляет время с учётом длительности и сеансов событий, считает переходы и строит маршрут.
В карточке плана точки можно заменить на альтернативы, добавить всё в «Мой план», открыть маршрут
и поделиться ссылкой. Планы хранятся в `data/plans.json`.

## Профиль и память

Профиль хранится на сервере в SQLite и синхронизируется между устройствами: в браузере по анонимному
идентификатору клиента, в Telegram по id пользователя (анонимный профиль склеивается с Telegram при первом
входе). Taste Graph учится на действиях: бронь, сохранение, выбор, добавление в план сдвигают веса к чертам
выбранных мест. История диалога с Claude и собранные вечера переживают перезапуск сервера и перезагрузку
страницы. Путь к базе задаётся переменной `FREE_DB`.

## Приложение и бэкенд

Приложение обращается к бэкенду по адресу из `app/app.config.json`. Сервер отдаёт CORS-заголовки
для origin приложения (`CORS_ORIGINS`, по умолчанию `capacitor://localhost` и `http://localhost`).
Пользователь идентифицируется анонимным идентификатором клиента (`X-Free-Client`); проверка подписи
Telegram (`TELEGRAM_BOT_TOKEN`) осталась как необязательный режим и по умолчанию выключена.
Развёртывание бэкенда на своём домене: [deploy/DEPLOY.md](deploy/DEPLOY.md).

## Проверка

```bash
npm run check   # синтаксис модулей + офлайн-тесты
npm test        # только тесты (node:test, без сети и зависимостей)
```

Тесты в `test/` покрывают разбор запроса (`buildSearchPlan`) и ранжирование
(`rankLive`, `placeDna`, `resultPayload`) на синтетических данных, поэтому
работают без доступа к KudaGo, Timepad и Overpass.
